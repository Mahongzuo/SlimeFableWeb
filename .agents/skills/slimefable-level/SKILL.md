# SlimeFable 关卡制作

每天的时光门背后是一段真实的历史。玩家扮演一团会变形的史莱姆，**亲身走进那一天**：有爽快的操作、有一个让人记住的高光时刻、离开时知道发生了什么。我们要做的是“沉浸式的小游戏”，不是“换皮跑腿任务”。

## 流程（按顺序，不许跳）

1. **读设计页**：`docs/days/MMDD.md`。设计页由 Opus 写或审。没有设计页就先写一份，交给 Opus 审，**审过之前不动工**。
2. **读参考**：`references/design-bar.md`（必须满足的标准）、`references/art-bible.md`（画面）、`references/templates.md`（玩法模板接口），以及设计页点名的好例子文件。
3. **搭建**：只改任务卡 `files:` 列出的文件。数据写在 `content/`，玩法写在 `src/templates/` 和 `src/level/`，画面写在 `src/themes/`。能复用的套件和模板先复用。
4. **自检**：
   - `node .agents/skills/slimefable-level/scripts/lint-content.mjs` 检查禁用内容和体积；
   - `npm run check && npm test`；
   - 按 `references/design-bar.md` 末尾的评分表自评，任何一项低于 4 分，先改再交。
5. **交付**：一段中文总结，写清楚做了什么、设计页的每一条是怎么落实的、自评分数、还没做到的地方。截图由 Opus 在浏览器里拍，你在总结里列出建议的截图机位（坐标和朝向）。

## 硬规则

- 史实只用设计页“事实卡”里带来源的内容。人物和情节可以虚构，但要在关卡文件顶部注释里写明“虚构”的范围。
- 简体中文。不出现日文假名。不画国家领导人肖像。Home 场景不挂任何旗帜。严肃事件不做战斗玩法。
- 不加贴图文件、字体文件、音频文件或新依赖。画面全部程序化生成：几何体、toon 材质、canvas 文字。
- 每关的代码和数据压缩后 ≤ 60 KB；共享套件要写成能被下一关复用的形式。
- 碰撞从网格烘焙。能穿过的物体名字带 `leaf/foliage/grass/flower/crop/water/fx` 之一，或者设 `userData.walkThrough = true`。
- 性能：一关新增的绘制调用 ≤ 150，重复物件用 InstancedMesh，update 里不要每帧 new 对象。

## 什么是“好关卡”（摘要，完整版见 references/design-bar.md）

1. **第一眼**：出生点就能看到这关的地标和年代感，不用读字就知道是哪里。
2. **一个高光时刻**：整关围绕它铺垫，比如剪彩、升旗、雷击、起飞。到那一刻要有镜头、特效和节奏变化。
3. **史莱姆的身体就是玩法**：至少用到两种史莱姆特有的能力（贴墙爬、分身压板、属性、摊开钻缝、游泳、弹跳），并且让它们和这段历史有关系，例如火属性点燃灶膛、雷属性接通电路。
4. **三层场景**：远景看轮廓，中景看结构，近景看生活痕迹；年代特有的 3 个细节必须出现。
5. **复玩**：至少 2 种挑战，比如计时奖牌、全收集、限制条件通关、隐藏纪念品、第二结局，并且写进存档。
